# 03. 스토리지: 데이터 디스크 분리와 LVM 무중단 확장

## 목적

- OS 디스크와 데이터 디스크를 분리해서, 데이터가 가득 차도 OS(로그, 원격 접속)는 살아 있게 한다
- LVM으로 구성해서 서비스를 멈추지 않고 용량을 늘릴 수 있게 한다

## 구성

| 서버 | 데이터 디스크 | VG | LV | 마운트 | fstab 옵션 |
|---|---|---|---|---|---|
| web | 10GB (nvme0n2) | vg_data | lv_www | /var/www | defaults |
| db | 10GB (nvme0n2) | vg_data | lv_mysql | /var/lib/mysql | defaults |
| backup | 30GB (nvme0n2) + 20GB (nvme0n3) | vg_data | lv_backup | /backup | defaults,nodev,nosuid,noexec |

- LV는 처음에 VG의 80%만 할당 (XFS는 축소 불가 → 작게 시작해서 필요할 때 확장)
- fstab에는 바뀔 수 있는 장치 이름 대신 LVM 경로 사용, 재부팅 전 `findmnt --verify`로 검증
- 새로 마운트한 경로는 `restorecon`으로 SELinux 라벨 복원
- backup은 실행 금지 옵션(noexec 등): 여러 서버의 데이터가 모이는 곳이라 악성 파일이 섞여도 실행되지 않게

## 확장 실습 결과

<!-- 아래 값은 예시입니다. 반드시 실제 측정값으로 바꾸세요. -->

| 단계 | 서버 | 크기 | 사용률 | VG 여유 |
|---|---|---|---|---|
| 확장 전 | web | 8.0G | 2% | 2.0G |
| VG 여유로 +1GB 후 | web | 9.0G | 2% | 1.0G |
| 공간 부족 연출 (22GB 파일) | backup | 24G | 93% | 6.0G |
| VG 여유 전부 사용 | backup | 30G | 75% | 0 |
| 디스크 20GB 추가 후 +15GB | backup | 45G | 50% | 5.0G |
| 테스트 파일 삭제 | backup | 45G | 1% | 5.0G |

측정 방법

- 크기, 사용률: `df -h <마운트 위치>`의 `Size`, `Use%`
- VG 여유: `sudo vgs`의 `VFree`


### 운영 기준 (런북에도 기록)

| 상태 | 디스크 사용률 | 조치 |
|---|---|---|
| 정상 | 80% 미만 | - |
| 주의 | 80% 이상 90% 미만 | 원인 확인, 정리 또는 확장 계획 |
| 위험 | 90% 이상 | 즉시 정리 또는 확장 |

## 위험 요소와 한계

- backup의 LV가 디스크 2개에 걸쳐 있어, 하나만 고장 나도 LV 전체를 잃을 수 있음 (중복 없음)
  - 실무 대응: RAID 또는 저장소 수준 복제 + 별도 백업
- 이번 실습은 VMware에서 VM을 끈 상태로 디스크를 추가함 (확장 자체는 무중단)

## 트러블슈팅

<!-- 이 단계에서 겪은 문제를 적습니다. 없으면 "없음"이라고 적어도 됩니다. -->

- 디스크 이름이 `sdb`가 아닌 `nvme0n2`로 표시됨: VM 디스크 종류가 NVMe라서 이름 규칙이 다름 (`nvme0n1`=OS, `n2`부터 추가 디스크)
